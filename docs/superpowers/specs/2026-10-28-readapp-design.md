# readapp 設計書（記事読み上げ → 専用ポッドキャスト）

- 作成日: 2026-10-28
- 対象者: 福田（本人のみが使う）
- 状態: 設計合意済み・実装前

## 1. 目的

地方在住で落ち着いて読書・記事を読む時間が取りにくいため、移動時間（車・電車/バス）や PC 作業中に、記事を Google の自然な音声 AI で「聞ける」ようにする。

## 2. 成功の基準

1. 本文の貼り付け（後のステップでは URL）から数分以内に、iPhone の Apple Podcasts に新しい回として届く。
2. 事前にダウンロードしておけば、圏外（山道など）でも途切れずに聞ける。
3. 費用は 0 円。Google の無料枠（Chirp 3 HD: 月 100 万文字）を超えない仕組みがアプリ側にある。
4. 日本語・英語の記事を自動で判別し、それぞれ自然な声で読む。

## 3. 決定事項と理由

| 決定 | 理由 |
|---|---|
| 再生は Apple Podcasts（専用の非公開番組） | オフライン保存・CarPlay・倍速・続きから再生を自作せずに使える。Spotify は非公開 RSS を登録できないため不採用 |
| 音声 AI は Google Cloud TTS（Chirp 3 HD） | 品質が最も高い。月 100 万文字まで無料 |
| アプリ側で月 90 万文字に達したら停止 | 無料枠を超えて自動課金されるのを防ぐ（「費用は一切かけたくない」） |
| 置き場所は Cloudflare（Workers / R2 / D1 / Access）の無料枠 | 福田がすでに使っており、費用 0 円で収まる |
| 原文の読み上げを基本とし、要約版は後のステップで追加 | 読書の代わりにするため原文が主。要約は NotebookLM 的な補助 |
| 対応言語は日本語・英語 | 福田の回答。中国語は対象外 |

### やらないこと

- 一般公開、他人の利用、課金の仕組み
- Spotify 対応、自作の再生アプリ
- 中国語の読み上げ
- 声・速度の細かい調整画面（速度は Podcasts アプリ側で変える）

### 不採用にした案

- 再生アプリの自作: iPhone の Web アプリはロック中の再生とオフライン保存が不安定で、開発量も多い。
- Google ドライブに MP3 を置く: 続きからの再生や車での操作性が弱い。
- Gemini API 無料枠の TTS: 制限が厳しく（1 分に数回程度）、上限も非公開で、長文に向かない。
- スマホ内蔵音声: 「Google の自然な音声 AI」という目的から外れる。

## 4. 全体構成

```
[iPhone/PC 入力画面] --本文/URL--> [Cloudflare Worker]
   1) 本文を取り出す（URL の場合）
   2) 文字数チェック（月上限・1 本上限）
   3) 文に沿って分割 --> Google Cloud TTS（Chirp 3 HD）
   4) 返ってきた MP3 を順につなげて R2 に保存
   5) D1 に記録し、RSS（番組一覧）に追加
[Apple Podcasts] <-- 秘密の RSS URL から新しい回を自動取得
```

| 部品 | 役割 | 技術 |
|---|---|---|
| 入力画面 | 本文貼り付け・URL 入力・回の一覧（処理中/完了/失敗） | Cloudflare Workers（TypeScript）、素の HTML |
| 認証 | 入力画面と API は福田の Google アカウントのみ | Cloudflare Access（無料） |
| 本文抽出 | URL から本文だけを取り出す（ステップ 2） | Mozilla Readability + linkedom |
| 言語判別 | 日本語文字の割合で ja-JP / en-US を決める | 自作の小さな関数 |
| 分割 | 文の区切りで、Google の 1 リクエスト上限（5,000 バイト）未満に分ける | 自作（メインセッションで実装） |
| 音声化 | 分割した文を順に音声化 | Google Cloud TTS REST API、MP3 出力 |
| 結合 | MP3 データを順に連結して 1 ファイルにする | 自作（メインセッションで実装） |
| 保存 | MP3 本体 / 回の情報・月の文字数 | R2 / D1 |
| 配信 | `/feed/<秘密トークン>.xml` で RSS を返す。MP3 も秘密トークン付き URL | Worker |

Podcasts アプリはログインできないため、RSS と MP3 は Access の対象外とし、推測できないトークンで守る。トークンは再発行でき、再発行すると古い URL は無効になる。

## 5. データ

D1:

- `episodes`: id, title, lang, char_count, status（processing / done / failed）, error, audio_key, audio_bytes, duration_sec, source_url, created_at
- `usage`: month（YYYY-MM）, chars_used
- `settings`: feed_token

文字数のカウントは、Google に実際に送った文字数（空白・改行を含む）で行う。月の区切りは Google の請求に合わせ、米国太平洋時間の暦月とする。

## 6. エラー時の動き

| 状況 | 動き |
|---|---|
| URL から本文を取れない | 「本文を取れませんでした。本文を貼り付けてください」と表示し、貼り付け欄を出す |
| 本文が短すぎる（200 字未満） | 有料記事の冒頭だけの可能性があるため、変換前に確認する |
| 月の上限（90 万字）を超える | 変換前に止め、今月の残りの文字数を表示する |
| 1 本が 5 万字を超える | 誤操作防止のため止める（長文対応はステップ 3） |
| TTS が途中で失敗 | その分割だけ最大 3 回やり直す。駄目なら途中の音声は配信せず「失敗」とし、再実行ボタンを出す |
| RSS の URL が漏れた | トークンを再発行する |

## 7. 開発ステップ

| ステップ | 内容 | 完了の確認 |
|---|---|---|
| 1 | 本文の貼り付け → MP3 → 非公開 RSS。月上限、認証、回の一覧 | 短い記事 1 本が Apple Podcasts に届き、福田が車で聞ける |
| 2 | URL からの本文抽出、iPhone の「共有」から送る（iOS 標準の「ショートカット」アプリ。アプリ自体の改修は最小限） | 無料記事 3 サイトで成功する |
| 3 | PDF の取り込み、長文（書籍の章）の分割処理、回の削除 | 本の 1 章を通しで聞ける |
| 4 | 要約版（Gemini API 無料枠） | 原文版と聞き比べて使える |
| 5 | メルマガを専用アドレスに転送すると自動で番組化（Cloudflare Email Routing） | 転送した 1 通が届く |

ステップごとに個別の実装計画を作り、完了確認後に次へ進む。ステップ 3 の長文処理では、Worker の実行制限に合わせて処理を分ける方法（Queues / Workflows など）を、その時点の無料枠で確認してから決める。

## 8. テスト

- 自動テスト（Vitest）: 言語判別、分割（文の途中で切らない／5,000 バイト未満）、文字数カウンターと上限判定、RSS の形式。
- テストでは本物の TTS を呼ばない（モックを使う）。文字数を無駄に消費しないため。
- 実機確認: 各ステップの最後に、福田が iPhone で確認する。

## 9. 開発体制

- メインセッション: 設計、レビュー、監査。難しい部分（分割と MP3 結合、上限の仕組み、長文処理）を担当する。
- 安価なモデルのサブエージェント: 画面、RSS、本文抽出、テストなど定型的な実装を担当する。
- 各ステップの流れ: サブエージェントが実装し、メインがレビューとテストを行い、福田が実機で確認する。

## 10. 福田が行う準備（ステップ 1 の実装時に手順書を用意する）

1. Google Cloud のプロジェクト作成、支払い情報の登録、Text-to-Speech API の有効化、API キーの発行。
2. Google Cloud の予算アラート設定（1 円でも請求が出たらメールで通知）。
3. Cloudflare で R2・D1・Access を有効化する（すべて無料枠）。
4. Apple Podcasts の「URL で番組を追加」で、秘密の RSS URL を登録する。
