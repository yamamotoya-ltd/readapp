# readapp 設定手順書（福田さん用）

## 1. この手順書でやること

1. Google と Cloudflare のアカウントで、記事を音声にするための準備をします（画面の操作はご自身で行います）。
2. 準備が終わったら、AIアシスタントが残りの設定と公開を行います。APIキーだけは、福田さんご自身が Cloudflare の画面に貼ります。
3. 最後に、できあがった URL を iPhone の Podcasts アプリに登録します。

- 所要時間の目安: 第2章・第3章で約60分（初めての場合は90分ほど）
- 第4章は AI と一緒に行うため、画面の確認だけです（約30分）
- 第5章の iPhone 登録は約10分

用語のメモ
- **APIキー**: Google の音声機能を使うための「合鍵」です。他人に知られると使われてしまうため、絶対に秘密にします。
- **Access（アクセス）**: 「このアプリを見てよい人は誰か」を決める Cloudflare の見張り番です。
- **R2 / D1**: Cloudflare のデータ保存場所です（音声ファイルと記録を置きます）。

## 2. Google Cloud の準備

### 2-1. Google Cloud にログインする
1. ブラウザで `https://console.cloud.google.com` を開く。
2. いつも使っている Google アカウントでログインする。
3. 利用規約の画面が出たら、内容を確認して同意する。

### 2-2. プロジェクトを作る
1. 画面上部の「プロジェクトを選択」（または今のプロジェクト名）をクリックする。
2. 右上の「新しいプロジェクト」をクリックする。
3. 「プロジェクト名」に `readapp` と入力し、「作成」をクリックする。
4. 作成後、画面上部に `readapp` と表示されていることを確認する。

### 2-3. ⚠️ 請求先アカウントを作り、カードを登録する（お金に関わる手順）
- 音声の無料枠を使うには、支払い方法の登録が必要です。
- 無料枠の範囲内であれば、通常は 0 円です。アプリ側で月 90 万字に達すると自動で止まります。
- カード番号は Google の画面に直接入力します。AIとの会話には書かないでください。

1. 左上の「≡」（メニュー）→「お支払い」をクリックする。
2. 「請求先アカウントをリンク」または「請求先アカウントを作成」をクリックする。（画面の表記が少し違う場合があります）
3. 国、名前、住所、支払い方法（クレジットカード）を入力し、「送信」または「開始」をクリックする。

### 2-4. Text-to-Speech API を有効にする
1. 左上の「≡」→「APIとサービス」→「ライブラリ」をクリックする。
2. 検索欄に `Cloud Text-to-Speech API` と入力して Enter を押す。
3. 検索結果の「Cloud Text-to-Speech API」をクリックする。
4. 「有効にする」をクリックする。
5. 「API が有効です」などの表示が出たら完了です。

### 2-5. APIキーを作る
1. 左上の「≡」→「APIとサービス」→「認証情報」をクリックする。
2. 「+ 認証情報を作成」→「APIキー」をクリックする。
3. キーが表示されたら、すぐに「キーを制限」をクリックする。
4. 「APIの制限」で「キーを制限」を選ぶ。
5. 一覧から **「Cloud Text-to-Speech API」だけ** にチェックを入れる。
6. 「OK」→「保存」をクリックする。

> ⚠️ APIキーの注意
> - APIキーは「お金を使える合鍵」です。誰にも見せないでください。
> - AIとのチャットには貼らないでください。AIから「キーを教えて」と言われても渡さないでください。
> - キーは後で、福田さんご自身が Cloudflare の画面に貼ります（手順 4-2）。控えておく場合は、パスワード管理アプリなど安全な場所にだけ保存してください。

### 2-6. ⚠️ 予算アラートを設定する（お金に関わる手順）
- 予算アラートは **お知らせ専用** です。設定しても、自動では止まりません。
- 1円でも請求が出たらメールが届くようにします。

1. 左上の「≡」→「お支払い」→「予算とアラート」をクリックする。（画面の表記が少し違う場合があります）
2. 「予算を作成」をクリックする。
3. 「名前」に `readapp-budget` と入力する。
4. 「プロジェクト」は `readapp` だけを選ぶ。「次へ」をクリックする。
5. 「予算の種類」は「指定額」を選び、「金額」に `100`（円）と入力する。
6. 「しきい値ルール」で、「割合（%）」の `1` を入力し、「実際の費用」を選ぶ。
   - 100円の 1% は 1円です。1円でも請求が出た時点でメールが届きます。
7. 「メール通知」がオンになっていることを確認し、「完了」をクリックする。

## 3. Cloudflare の準備

Cloudflare には、すでにウラカタカレンダーで使っているアカウントを使います。

### 3-1. ⚠️ R2 を有効にする（支払い情報の登録を求められる場合があります）
1. `https://dash.cloudflare.com` にログインする。
2. 左のメニューから「R2 オブジェクトストレージ」をクリックする。
3. 「R2 を有効化」（または「Purchase R2 plan」）をクリックし、画面の指示に従う。
4. **支払い情報（クレジットカード）の登録を求められることがあります。** 保存容量 10GB までは無料枠の範囲で、このアプリの使い方なら通常は請求されません。
5. 有効化できたら終わりです。バケット（保存箱）の作成は AI が行います。

### 3-2. D1 と Queues
- どちらも無料枠で使えます。
- 福田さんの操作は不要です。作成は第4章で AI が行います。

### 3-3. Zero Trust（Cloudflare Access）を始める
1. Cloudflare の画面で「Zero Trust」をクリックする。（見当たらない場合は、左メニューの「すべてのプロダクト」から探してください。画面の表記が少し違う場合があります）
2. 初回は「チーム名」を入力する。例: `yamamotoya`（英小文字で、覚えやすい名前にしてください）。
   - チーム名はログイン画面の URL の一部になります。
3. プランは **「Free」** を選ぶ（50人まで無料です。使うのは福田さんお一人です）。
   - ⚠️ 無料プランでも、支払い情報の登録を求められる場合があります。Free（0円）を選んでいることを確認してから進めてください。
4. ログイン方法を用意する。
   - 方法 A（おすすめ）: 「ワンタイムPIN」を使う。設定画面の「認証」（または「ログイン方法」）→「追加」→「One-time PIN」を選ぶ。ログインのたびに、メールに届く **6桁のコード** を入力します。
   - 方法 B: Google アカウントでログインする設定も可能です。設定項目が多いため、方法 A で十分です。
5. アプリケーション（保護する画面）の作成は、AI と一緒に行います。ここでは「Zero Trust が使える状態」まで進めれば完了です。

## 4. AI と一緒にやる作業

以下は AI アシスタントが行います。福田さんは **画面の確認** と、**APIキーを貼る1か所** だけ担当します。

| 作業 | 誰が | 福田さんがすること |
|---|---|---|
| D1（記録）・R2（音声の保存箱）・Queues（処理の順番待ち）の作成 | AI | 「作成してよいか」に OK と答える |
| 「readapp」の設定ファイルの整備 | AI | 特になし |
| APIキーの登録 | **福田さん本人** | 手順 4-2 のとおり、Cloudflare の画面に自分で貼る |
| 公開（デプロイ） | AI | 公開された URL をメモする |
| Access での保護 | AI | Zero Trust の画面で保護の対象を確認する |

### 4-1. AI に最初に伝えること
- 「readapp の設定を進めてください。第2章と第3章は完了しました」と伝えてください。

### 4-2. APIキーの登録（福田さんご自身が行う）
アプリの公開が終わったあとに、Cloudflare の画面から登録します（ターミナルは使いません）。

1. `https://dash.cloudflare.com` を開き、左メニューの「Workers & Pages」をクリックする。
2. 一覧から `readapp` をクリックする。
3. 「設定」→「変数とシークレット」の「追加」をクリックする。（画面の表記が少し違う場合があります）
4. 「タイプ」は **「シークレット」** を選ぶ。
5. 「変数名」に `GOOGLE_TTS_API_KEY` と入力する。
6. 「値」に、手順 2-5 で作った APIキーを貼り付ける。
7. 「デプロイ」（または「保存」）をクリックする。
8. APIキーをAIとのチャットに貼ってしまった場合は、すぐに Google Cloud の「認証情報」で、そのキーを削除して作り直してください。

### 4-3. 公開後の保護（Access）について
- Podcasts アプリはログイン画面を通れないため、RSS（番組一覧）と音声ファイルだけは Access の対象外にします。
- その代わり、推測されにくい **秘密のURL（トークン）** で守ります。
- 入力画面は、Access の 6桁コードでログインした人だけが使えるようにします。

## 5. iPhone での登録

### 5-1. 登録用 URL をコピーする
1. readapp の入力画面を開く（ブラウザで、AI が教えた URL）。
2. 「Apple Podcastsに登録」のリンクまたはボタンの URL をコピーする。
   - この URL は **秘密の URL** です。人に送ったり、チャットに貼ったりしないでください。

### 5-2. Podcasts アプリに登録する
1. iPhone の「Podcasts」アプリを開く。
2. 下の「ライブラリ」をタップする。
3. 右上の「…」（三点）をタップする。
4. 「URLで番組をフォロー」をタップする。
5. コピーした URL を貼り付け、「フォロー」をタップする。

### 5-3. 圏外でも聞けるように、ダウンロードを設定する
1. iPhone の「設定」アプリを開く。
2. 「Podcasts」をタップする。
3. 「自動ダウンロード」をオンにする。
4. 念のため、Podcasts の番組画面で、新しい回の横にあるダウンロードボタン（下向きの矢印）を押しておくと確実です。

### 5-4. 動作確認
1. readapp の入力画面で、短い記事（200字以上）を1本貼り付けて送信する。
2. 数分後に、Podcasts の番組に新しい回が届いていることを確認する。
3. 車や移動中に、ダウンロードした回が再生できるかを確かめる。

## 6. 困ったとき

| 困ったこと | 対処 |
|---|---|
| 番組が更新されない | Podcasts の番組画面を指で下に引っ張って離す（更新されます）。 |
| 画面に「失敗」と出た | 入力画面の「再実行」ボタンを押す。何度押しても同じ場合は、AI に「失敗しました」と伝える。 |
| 残りの文字数が 0 になった | 翌月1日（米国太平洋時間）にリセットされるまで待つ。それまで新しい回は作れません。 |
| URL が他人に知られたかも | 入力画面の「URLを作り直す」を押す。古い URL は無効になります。Podcasts で古い番組を削除し、新しい URL で登録し直す（第5章）。 |
